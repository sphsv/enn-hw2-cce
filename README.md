# Cut Your Losses: статья и воспроизведение

В этой папке собраны три части работы:

1. [Презентация](presentation/cce_article_explained_ru.pdf) объясняет статью,
   а не локальные эксперименты.
2. [Отчет](report/reproduction_summary.md) описывает выполненные эксперименты,
   основные результаты и ограничения воспроизведения.
3. `src/`, `scripts/`, `configs/` — код и настройки для повторения экспериментов.
   `results/` содержит уже полученные измерения и графики.

## Где что лежит

```text
HW2/
├── presentation/       PDF с объяснением статьи.
├── report/             Отчет о локальном воспроизведении.
├── configs/            Размеры задач, методы, seed, число повторов.
├── src/                Эксперименты, обработка результатов, графики, проверки.
├── scripts/            Команды запуска на машине с GPU.
└── results/
    ├── raw/            Исходные измерения и журналы обучения.
    ├── processed/      Сводные таблицы и статистика из raw.
    └── figures/        Графики из этих измерений.
```

`raw` — исходные данные, их не нужно заменять ради новых формулировок отчета.
`processed` и `figures` можно получить заново из `raw`.
`raw/environment.json` фиксирует окружение, в котором выполнялись GPU-запуски.
Файлы `*_manifest.json` фиксируют параметры и завершение каждого обучения.
Перед публикацией абсолютные пути машины в метаданных заменены относительными.
Численные измерения, параметры и версии окружения не менялись.

### Где сама реализация CCE

GPU-ядра взяты из [официального проекта Apple](https://github.com/apple/ml-cross-entropy).
Этот комплект содержит собственный код экспериментов, но не собственную
реализацию ядер CCE. Официальный код загружается в `external/ml-cross-entropy`
на коммите `3de376c106a1916bc5e1b619f9c77c87a461ee1c`.
В локальном комплекте папка `external` не включена.

Это более новая версия кода, чем использованная в статье. Также отличается
окружение: A100 80 ГБ, Python 3.12.3, PyTorch 2.9.1+cu128, Triton 3.5.1.

### Что делает код

| Файл в `src/` | Назначение |
|---|---|
| `correctness.py` | Сравнивает лосс и градиенты CCE с обычной кросс-энтропией. |
| `table1_extended.py` | Измеряет память и время методов из таблицы 1. |
| `scaling.py` | Проверяет, что происходит при увеличении словаря. |
| `filtering.py` | Сравнивает CCE с фильтрацией градиентов и без нее. |
| `figure3_probabilities.py` | Строит распределение вероятностей по рангам токенов. |
| `training_entrypoint.py` | Запускает официальное обучение и добавляет запись метрик по шагам. |
| `summarize.py` | Собирает сводные таблицы из отдельных замеров. |
| `summarize_figure4.py` | Обрабатывает 10 запусков обучения, сравнивает кривые и считает интервалы. |
| `plot_results.py` | Строит графики из исходных данных и сводных таблиц. |
| `validate_results.py` | Проверяет часть требований к комплектности результатов; это не GPU-тест. |
| `capture_environment.py` | Записывает версии библиотек, GPU и коммит официального кода. |
| `annotate_official.py` | Добавляет описание запуска к CSV официального измерителя. |
| `repro_utils.py` | Общие функции: чтение настроек, seed, обычная кросс-энтропия, метрики ошибок. |

`scripts/run_official_benchmark.sh` запускает основные три метода;
`run_table1_extended.sh` — расширенную таблицу;
`run_figure4_gemma.sh` — пять пар запусков обучения.
`run_training.sh` используется внутри последнего скрипта.

### Границы воспроизведения

Ограничения для отчета:

- Память выходного слоя и лосса — не память всей модели: входные веса и
  скрытые состояния уже находятся на GPU до измерения.
- CCE уступает `torch.compile` по времени в основном сохраненном замере.
  Нельзя делать общий вывод, что CCE всегда быстрее всех методов.
- Обучение выполнено на одной GPU с глобальным батчем 8; в статье — 8 GPU
  и батч 64. Результат показывает близость двух методов в локальном режиме.
- Последний лосс CCE немного выше: парная разница последних 50 шагов
  `0.000546`, 95%-й интервал `[0.000266; 0.000825]`. Это не строгое равенство.
- Названия Kahan относятся к текущим официальным режимам накопления в FP32,
  не к запуску исторических ядер статьи.
- Seed в CSV официальных замеров добавлен из конфигурации как метаданные.
  Сам официальный генератор Gemma использует свой `random.Random(0)`;
  локальное поле `seed` не управляет выборкой этого генератора.
- Остальные модели рисунка 4, предобучение из рисунка 5 и полный набор
  официальных тестов не воспроизводились.

## Повторный запуск на GPU

```sh
mkdir -p external
git clone https://github.com/apple/ml-cross-entropy.git external/ml-cross-entropy
git -C external/ml-cross-entropy checkout 3de376c106a1916bc5e1b619f9c77c87a461ee1c
python3.12 -m venv .venv
.venv/bin/pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cu128
.venv/bin/pip install -r requirements-machine.txt
.venv/bin/pip install --no-deps -e external/ml-cross-entropy
.venv/bin/hf auth login
```

`requirements-machine.txt` фиксирует полное окружение измерений;
`requirements-benchmark.txt` — зависимости без тяжелого PyTorch/Triton.
`setup_remote_env.sh` — альтернативная установка с использованием уже
имеющегося окружения GPU через `BASE_PYTHON`, если нужно экономить место.

```sh
make environment correctness scaling filtering figure3
scripts/run_official_benchmark.sh
scripts/run_table1_extended.sh
scripts/run_figure4_gemma.sh
make summaries plots validate
```

Команды могут заменить соответствующие
файлы в `results`; предыдущие измерения нужно сохранять отдельно.
`run_figure4_gemma.sh` пропускает журналы с нужным числом шагов,
поэтому для полностью нового обучения старые журналы следует сначала архивировать.
